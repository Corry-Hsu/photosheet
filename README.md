# 地籍任務靜態版 v1（候驗版）

這是適用 GitHub Pages 的網站，不需 Python、資料庫、登入或 GitHub 寫入憑證。原本後端版本仍另外保留，本包不會啟動後端。

## 首次部署

1. 解開網站 ZIP。把 `index.html`、三個 `worker-*.html`、JS、CSS、`vendor` 與 `data` 等檔案上傳到 GitHub 專案根目錄。不要再多包一層資料夾。
2. 在 GitHub 專案 Settings → Pages，選擇 Deploy from a branch、正確分支與 `/ (root)`，等待部署完成。
3. 若專案仍是 Corry-Hsu/photosheet，預期網址為 `https://corry-hsu.github.io/photosheet/`，以 Pages 顯示的實際網址為準。網站由 main 分支根目錄部署；部署結果可在 GitHub Pages 與 Actions 檢查。
4. 管理頁是根網址；現場固定入口依序為 `worker-1.html`、`worker-2.html`、`worker-3.html`。

請透過 HTTPS 網站使用。直接雙擊 HTML 的 `file://` 模式無法完整運作。需要本機測試時，在網站資料夾執行 `python -m http.server 8000`，用 `http://localhost:8000` 開啟；手機連電腦的一般 HTTP IP 網址不保證能取得相機及定位權限。

## 初次建立資料

1. 在管理頁匯入工作 Excel，勾選類型、核對提醒與日期後確認。一行紀錄是一筆任務；不拆成每地號一筆。
2. 匯入地籍 ZIP（可直接選 T.zip，不需手動解壓），或同時選擇 KML 與 XML。先在電腦建立完整索引，再分派給現場手機。
3. 支援 KML 的 `SECTNO`／`PARCELNO` 欄位，以及 Placemark 名稱 `0582/1198`（段代碼／地號）。Excel 數字段碼582會正規化為0582，子號支援1198-1。單獨KML即可用代碼配對，不必另外匯入XML；地段名稱從Excel取得。也支援原有Lands XML地籍資料。
   匯入時會讀取Excel「段」對照表；舊資料有XML地籍名稱對照時，也可取得正確段碼。若來源列段碼與對照不同，保留原值，配對採對照代碼，但頁面不顯示配對成功／失敗提示。跨地段任務各自使用對應代碼，無唯一對照時不擅自套主地段代碼。
4. 不讀取外部 NetworkLink，不執行公式、HTML、DTD 或外部實體。KMZ 不在本版支援範圍。KML 使用標準 WGS84「經度,緯度」座標，禁止把投影公尺座標直接當經緯度。
5. 同一段代碼與地號在不同圖幅的範圍合併，完全相同的幾何片段去重。無效或退化邊界會列出提醒，不拿別筆地籍替代。
6. 在任務詳情核對全部地號。未配對可透過「修正地段地號」補正；修改前地號留在管理備份中。地籍範圍缺漏時仍可手動設定導航入口。
7. 選擇任務後，清單與地圖同步。點圖、拖動橘色圖釘或輸入經緯度可設定已核對入口；自動代表點只標示「地籍參考位置」。地籍點不保證車輛可達。

## 日常派工與發布

1. 三人設定可更改姓名，網址不變，包含自己最多三人。
2. 勾選任務，批次設定負責人、成果指定日期及期限。日期空白表示維持原值。
3. 成果日期預設取 Excel「通知」。期限預設取原表「完成」日期加臺灣時間 17:00，需自行核對。
4. 上月以前未派案不能新增分派；舊已派案保留原人、不可改派；解除後不能再派。此限制會在本機保存，不能藉改日期重開。它是作業規則，不是防止刻意修改資料的權限機制。
5. 點「產生三人發布檔」，檢查每人的任務數、缺日期／缺位置提醒，下載 ZIP。
6. 解開 ZIP，把 `data` 裡三份 JSON 一次上傳到 GitHub 的 `data` 目錄。網頁只產生檔案，不會自行推送 GitHub。
7. 等 Pages 部署完成，現場人員按「重新整理派工資料」，核對批次與時間。三份檔案均需替換，避免留下上一批任務。

公開 Pages 的任務資料與地籍範圍可被其他人讀取；三個網址不構成權限隔離。不要發布不宜公開的案件或個資。原 XML 的統一編號、權利人資料不會被抽進地籍索引；發布包只放派工用到的地籍，不放完整索引、Excel、XML 或照片。

## 白板與工作單

- 管理頁可單筆／批次輸出白板及工作單；現場頁可輸出自己的白板。
- 白板為 A4 橫式，日期、地段、全部地號最大化顯示，底部兩行廠商／人員，無框線及多餘標題。列印請關閉瀏覽器頁首／頁尾。
- 工作單為 A4 直式。圍籬用「開口契約訂單通知表」，砍樹與雜草垃圾用「工作通知單」。保留整案數量，不按地號重複加計。
- 白板在原頁預覽並直接產生 PDF 與 PNG（2400×1697），不需要開啟空白分頁或透過手機列印轉檔；多筆可下載合併 PDF 或全部圖片 ZIP。Excel 輸出保留。
- 工作單維持列印／另存 PDF 與可編輯 Excel，沿用欄位重建格式，不是原 Excel 的逐像素複製；正式發文前核對契約內容。
- 工作單需要允許開啟文件視窗。白板可直接下載 PDF／圖片，手機可從檔案預覽儲存或分享。

## 現場照片

- 網頁相機按下拍攝時記錄時間；定位成功後製作浮水印並暫存。預設橫式4:3中央取景，取景框與成果一致，原圖另存。日期用任務指定日期，時分秒用拍攝當下臺灣時間，附 GPS 與精度。浮水印預設放在照片底部水平置中，透明背景、白字加陰影，不加黑色底板。
- 原生相機入口必須能讀到 EXIF 拍攝時間；缺少時不猜測，提示改用網頁相機。原生 EXIF 無時區時按臺灣時間解讀，僅適用本案臺灣現場使用。
- 無 GPS 不產生假座標成果；可重新授權再拍。此版未保存失敗拍攝的草稿，權限／定位失敗時需重試拍攝。
- 照片只存本機 IndexedDB，不回傳。可下載原圖、浮水印圖或整案 ZIP。成果輸出橫式4:3 JPEG，長邊最多 4096px；原圖另存，保留原始尺寸。
- 每筆提示至少兩張並顯示本機張數，不會標記任務完成。更換派工資料不改寫舊照片。
- 裝置時間、GPS、EXIF 不提供防偽保證。手機儲存不足、清除網站資料、無痕模式關閉都可能讓暫存消失，請主動下載。

## 備份與資料量

- 管理資料及地籍索引只在目前瀏覽器，不會在兩台電腦自動同步。下載「本機備份」後，可在另一台裝置還原。備份不含照片，請另外下載照片。
- 管理備份不要上傳 GitHub。還原須確認取代；壞檔不覆蓋原資料。管理資料與地籍索引在同一筆交易還原。
- 真實資料約 17.6 萬筆土地、310 萬個有效邊界點，首次匯入建議用電腦，手機只載入分配給自己的子集。
- 地籍索引每 1,000 筆分片存放，避開瀏覽器單筆大小上限；取消或儲存失敗不會留下半套索引。仍受裝置容量與瀏覽器配額限制。
- Excel 上限 12MB，解壓後 80MB／4,000 個內部檔案；地籍 ZIP 每包解壓後上限 1GB／30,000 檔案，單一 XML/KML 解壓上限 48MB。
- 不保證離線重新開啟整個網站，未加入 Service Worker。底圖需連網；底圖故障不影響本機地籍計算與既有導航連結。

## 地圖來源與限制

Leaflet + OpenStreetMap 標準底圖，保留來源標示，不批次預抓或離線快取瓦片。大量公開使用前，應依底圖政策選擇合適供應商。導航用 Google Maps 官方網址，不含 API 金鑰。

## 驗收狀態

自動化驗證結果另附報告。這是候驗版，尚未在真正 Android Chrome、iPhone Safari 測試實機權限、儲存／分享、列印與導航，也尚未上線 GitHub Pages；不能以模擬相機測試代替實機驗收。

## 現場清單（2026-10-27）

現場頁優先顯示緊湊任務列，每頁最多50筆；搜尋在頂部，篩選與批次選取按需展開。點任務列會同步定位並帶往下方地圖；地圖旁的「任務內容／拍照」或任務列箭頭可開啟詳情。清單與地圖同頁顯示，地圖有「導航前往」按鈕，使用所選任務位置開啟Google Maps。注意事項、批次資訊與重新整理位於地圖後方的「注意事項與派工資訊」。

## 管理清單日期與完成註記

- 以成果指定日期為準，只顯示今年、本月1日起到年底的任務；舊月份、其他年度及缺日期資料不列入清單、統計或批次選取，但保留在本機資料與備份。此限制不會移除現場既有派工包。
- 管理者可在清單或詳情標記／取消已完成，也可批次操作，並篩選全部、未完成、已完成。完成註記及時間保存在本機管理資料，與備份一併保存。
- 已完成任務不可直接重新分派，須先取消完成。產生派工檔會排除已完成任務；三人皆無待辦時仍可產生空清單，用於移除舊派工。因為是靜態網站，完成註記不會自動改寫現場網址：須產生並發布新派工檔後才更新。

地籍配對在背景自動執行。清單、詳情與發布確認不顯示配對結果標籤、數量摘要或配對狀態篩選；地段地號、地圖、導航、完成狀態與資料匯入錯誤提示保留。
