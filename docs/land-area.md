# 線上地籍面積配對

## 操作

1. 在管理頁匯入 Excel 或手動建立任務。上方「配對地籍面積」會處理已勾選任務；若沒有勾選，處理目前篩選結果的全部任務，包含其他分頁，不包含隱藏舊案。
2. 開啟後自動讀取 `data/land-area/catalog.json`，再按任務的縣市、鄉鎮、地段及段代碼讀取必要的地段 JSON。同一地段只讀一次，不下載全部地籍。
3. 核對「目前面積 → 登記總面積」及各地號明細。完整配對的任務才能勾選；未完整配對只顯示已配對小計，不當成整案總面積。
4. 勾選後按「套用勾選任務的登記總面積」，儲存在本機管理資料。也可從任務詳情的「線上配對面積」只處理該筆任務。
5. 工作單 Excel／列印會使用套用後的面積，人員與廠商發布包亦包含該面積及該任務的配對明細。發布仍沿用原本整理差異、匯出與上傳流程；不會自動修改網站上的派工 JSON。

## 計算與保護

- 一筆 Excel 紀錄仍是一筆任務，總面積為該任務全部不同地號的「登記面積」之和，不修改工作項目的施作數量，也不依持分計算。
- 使用精確十進位計算，保留最多六位小數，不使用浮點直接加總。0 為有效面積，缺漏值不當作 0。
- 配對須符合縣市、鄉鎮與地段；段代碼存在時也必須一致。同名地段不能任意取第一個；缺檔、缺地號、衝突、不同單位或讀取錯誤不能套用成完整總面積。
- 精簡資料已將相同地號且面積相同的所有權紀錄去重；面積衝突仍保留問題標記，不猜測正確值。
- 原 Excel 面積保留在 `originalArea`；`landArea` 保存本次總面積、地號明細、來源檔、核對時間及地籍簽章，包含於管理備份。發布包只附該任務的精簡明細，不附完整地籍資料庫。
- 新增或修正地籍後，已計算的 XML 面積會失效、清空目前 `area`，並提醒重新配對；先前總面積留在追溯資料，不繼續套到新地號上。整理發布檔時若修改地籍，也會清掉失效的推算面積。原本單純由 Excel 填入而未經 XML 配對的面積不自動清除。
- 配對結果尚未套用前若地籍已變更，整批拒絕套用。儲存失敗會回復全部變更，可重試。預覽本身不改動任務。
- 只做同站唯讀 GET，不需要資料庫、GitHub 寫入憑證或後端。現場頁不顯示管理用配對工具。

## 本次資料

來源：使用者於 2026-11-11 提供的本機精簡 ZIP。907 個地段，182,597 筆不重複地號；原 182,816 筆紀錄中合併 219 筆重複。907 份 XML 均成功轉換，manifest 的 881 份檔案全部存在；面積問題與無效地籍列均為 0。

已對所有地段 JSON 逐檔驗證，只保留縣市、鄉鎮、地段、段代碼、地號、面積及問題標記，沒有所有權人、統一編號、持分、管理者或原始 XML。依臺灣土地登記慣例以平方公尺（㎡）表示；原 XML 未另列單位欄位。

此資料是提供時的地籍快照，不代表即時地政查詢，之後更新需重新產製地段檔及索引。

## 更新資料與驗證

使用 `tools/build_land_area_catalog.py` 在本機轉換完整來源資料，再上傳產出的精簡 ZIP 供審查。`catalog.json` 每個項目指定固定四位段碼及同名 JSON 路徑，不能包含任意 URL 或上一層路徑。

自動驗證：

```sh
python tests/land_area_converter_test.py
node --test tests/core.test.cjs tests/dispatch-plan.test.cjs tests/land-area.test.cjs
AREA_TEST_URL=http://127.0.0.1:8806/ python tests/land_areas_qa.py
```

完成條件：只讀必要地段；完整地號去重後精確加總；預覽不改資料；部分與衝突配對不能套用；儲存失敗整批回復；地籍變更拒絕舊預覽且使舊總面積失效；工作單與實際人員／廠商 JSON 包含新面積；原有任務、導航、KML、工作數量及派工檔不受影響；手機與電腦版面無水平溢出。
