# 文件任務交換

此功能讓本機地籍文件產生器取代Excel作為案件來源，photosheet繼續負責指派、完成、導航及靜態發布。它不是管理備份還原，也不會自行修改GitHub資料。

## 操作

1. 在地籍文件產生器勾選案件，按「匯出派工任務」，下載JSON。
2. 開啟photosheet管理頁，按「匯入文件任務」選檔。新案預勾選；同ID既有案展開逐欄差異，預設維持派工端資料。
3. 明確勾選地號、日期、工作項目或面積等需要更新的欄位，確認合併。未選任務不變，未包含任務不刪除。
4. 新案初始不指派，請按原流程分派。完成、舊案鎖及導航不因匯入改掉；即使勾選成果日期更新，原舊案鎖也保留。需要重新開放舊案請使用原有功能。
5. 地號更正不會猜測或重設已確認導航，請在原管理地圖另外核對入口。新KML可加入，已有不同範圍維持原值並提醒；若需修正請走原地籍核對流程。
6. 完成後使用「整理發布」或「發布派工」。網站data仍需按原方式上傳核對過的六入口JSON；文件交換檔不是發布包，不能直接放進data。

匯入期間發現其他視窗更新任務或地籍時，會整批拒絕，請重新匯入核對。儲存失敗不套用一半資料；本機照片不刪除或搬移。從同一文件案件重複匯出應保持task.id，重匯不會因地號相同拆成多案或跨工種合併。

## 契約

kind=`cw015-dispatch-tasks`、schemaVersion=1，含projectId、exportId、exportedAt、tasks、features。task.id保持來源ID，包括既有Excel ID及文件工具新增ID。

任務白名單：工種、序號、案號、通知日、成果日、期限、廠商、人員、登記面積、全案地籍、items。items保留slot、名稱、數量、單位、備註及diameter徑級，支援文件工具的六項樹木工作。地籍以縣市、鄉鎮、地段、四碼段代號與正規化地號識別。

交換檔拒絕assignee、completed、assignmentClosed、assignmentLockedTo、navigation及其他未支援欄位。原派工端未知欄位保留；同ID不同工種拒絕，不嘗試用裸地號改變任務身分。新案source=`cw015-document`，不自動指派；原派工分類與顯示規則沿用。

地籍只接受相關KML及白名單地籍描述，不帶XML權利人。原Excel、來源備份、照片、簽名、圖例與截圖均由文件專案保存，不放進此格式。

## 驗證

`node tests/document-task-core.test.cjs`：格式、欄位投影、六工作項目、選欄更新、生命週期及舊案鎖保留、新增、重匯、錯誤欄位、同ID工種衝突及地籍衝突。

`node tests/document-task-import-browser.test.cjs`：合成資料操作真正管理頁，驗證追加／選欄、既有照片與無關案保留、拒絕錯誤封包、重匯、其他視窗更新時拒絕、儲存失敗原子回滾及原廠商發布JSON有效。需要Playwright；Windows用Edge，其他平台用Chromium。此測試不修改公開data；原始證據只在evidence/document-task-import，不能提交私人證據。

本機合成測試不等於iPhone／Android實機或全套相機驗證。原外部圖資可用性、本機與正式網站各自的IndexedDB也不能視為自動同步。
