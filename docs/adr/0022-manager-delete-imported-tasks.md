# ADR-0022：管理頁逐筆刪除各來源任務

- 狀態：已採用；2026-11-26（Asia/Taipei）。
- 起點：`ddad59222b17e435dd0f2c070524a56cf20b8639`（main，保留最新公開資料）。
- 取代關係：局部取代 ADR-0002／規格R-04「僅手動來源可刪」限制；確認、寫入失敗回復、照片及共用地籍保護沿用。文件交換與發布去重決策不變。
- 來源：使用者指出跨來源匯入後有重複任務，但Excel／文件來源沒有刪除入口；截圖顯示兩筆期限不同，不能直接替使用者選擇保留哪筆。

## 決策與理由

管理頁清單與詳情對所有來源提供逐筆「刪除任務」，包括手動、Excel、文件匯入、舊版來源；不以serial是否空白決定可刪與否。管理者每次需確認來源、task.id、工作類型／案號、全部地號、成果日期與期限，確定後只按該唯一ID移除一案。詳情補正來源標籤並顯示可換行ID，避免文件任務被稱作「原表第0列」。

找不到ID、ID為空或同一ID對應多筆時拒絕，不讓一次操作誤刪多筆。儲存期間停用重複操作，失敗回復原任務與可重試狀態，成功後清理選取／地圖／分頁並更新月統計。共用地籍與所有照片不刪，也不搬移照片到保留案。人員／廠商頁仍沒有刪除入口。

## 未採方案

未自動判重、依地號合併、以期限缺漏或匯入先後猜要刪哪筆、不提供一鍵刪除所有疑似重複、不順便清空舊案。未改寫Excel或文件來源檔、公開data或GitHub，也未新增來源對照或刪除墓碑；各匯入既有去重規則保留。

## 影響與限制

只改管理刪除來源限制、確認資訊、詳情來源／ID與管理資源版本。任務ID、工作量、導航、未刪案、檔案匯入及照片格式不變。本機刪除不會移除已公開派工，仍需發布工作區核對並重新發布；相簿照片雖保留，建議刪除前完成需要的備份。若原始檔仍含已刪任務，重新匯入可能再加入，不宣稱永久跨來源去重。

## 實際驗證

`manual_delete_qa.py`沿用歷史名稱，現涵蓋各來源管理刪除：來源／ID／日期確認、相同地號不同ID與期限仍分案、取消、文件寫入失敗與重試、空serial Excel刪除、重複／不存在ID拒絕、待存停用重複操作、選取／地圖／分頁清理、共享KML與照片保留、發布快照不含已刪案，以及人員／廠商隔離。多選地圖、月統計與文件匯入必要回歸亦通過，共四組。開發中測試選擇器與重載後儲存fixture失敗已修正，未放寬資料保護。詳見[交接](../HANDOFF.md)及[驗證紀錄](../verification/delete-imported-tasks.json)。

未讀取或刪除使用者瀏覽器內的真實案件，未跑全套、實機、WebKit；原生多頁GPS未解仍保留。缺乏實際兩筆task.id／來源資料，未確認該案例重複產生的完整歷史。
