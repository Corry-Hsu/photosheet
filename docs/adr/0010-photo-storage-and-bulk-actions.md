# ADR-0010：本機照片、失敗重試與勾選批次處理

- 狀態：已採用（本次回溯整理；原始實作時間見PR）。
- 整理日：2026-11-20；核對基準：8258a42。
- 證據與範圍：[PR #13](https://github.com/Corry-Hsu/photosheet/pull/13)、[#42](https://github.com/Corry-Hsu/photosheet/pull/42)；[field-camera.js](../../field-camera.js)、[db.js](../../db.js)。

## 背景

現場逐張儲存已足夠，詳情需更快打包或刪除；重複存原圖與編碼、關開相機、每次重取定位會拖慢連拍。

## 決策／改了什麼

照片以person＋taskId存本機IDB，位元組格式相容舊Blob。靜態新照片僅保存主要浮水印成果，舊原圖仍可讀；定位5秒內重用，取像並行定位，重試沿用blob與ID。詳情改勾選ZIP／批刪，寫入交易保護，存好才回取景。

## 為什麼

直接回應使用者效率與保存習慣；位元組儲存是因WebKit Blob交易可能失敗的相容處理，不是新的雲端儲存。

## 未採用／已取代的方案

不採每張詳情附儲存／刪除、ZIP收原圖與其他任務、失敗就清掉當次圖片、分享取消即刪除、每拍一張重開相機。未在靜態版啟用兩張回傳自動完成。

## 影響與取捨

清網站資料仍可能遺失照片；共享備份不帶照片。照片可包含GPS文字但未必有EXIF，CW015若要讀此種照片需另外本機OCR，並非photosheet已做的功能。
