# ADR-0018：底部中央圓形快門與上方鏡頭設定

- 狀態：已採用。
- 核對基準：`67c6e030aed2fe5d3fe23dc04e7a59dbf96acbf6`（main，已合併PR #53）。
- 取代關係：取代 ADR-0017 同一底部控制區以分隔線區隔的呈現；局部取代 ADR-0009 橫式全部控制共用單列的布局。固定倍率、鏡頭能力、滿寬原比例、浮水印與照片生命週期沿用。
- 來源：使用者提供參考相機，指定快門獨立置中、圓形無文字、焦距按鈕遠離快門。

## 決策與理由

快門為76×76 CSS px白色圓形，外框與內圈提高辨識，底部中央獨立一列；沒有可見「拍照」文字，但保留原生button、`aria-label="拍照"`、鍵盤操作與焦點標示。鏡頭選單與0.5×／0.75×／1.0×移到取景上方，和標題共同固定；600px以上橫式的鏡頭與倍率在上方共用一列，快門仍在底部中央。

設定與快門由取景區隔開，不在影像上覆蓋設定，也不為騰空間裁切或縮小原影像。拍後鏡頭／倍率依既有流程隱藏，儲存與失敗重試保留文字按鈕，成功後點照片返回連拍。

## 未採方案

未只改成小圓鈕留在倍率旁、未收合選單或縮小44px鏡頭控制、未增加說明文字。參考圖的2×、錄影、濾鏡、定時器與縮圖不是本次需求，不加入；保留既有真實能力才啟用的三倍率，不假造焦距。

## 影響與限制

更動現場相機HTML生成布局與CSS、六個入口的JS/CSS版本；拍攝、定位、浮水印、照片儲存及相簿邏輯不變，公開data不動。上下固定區會占用部分視窗，長影像沿用原比例滿寬、可捲動，不宣稱整張照片一次可見。

## 實際驗證

人員／廠商各390×844、320×568、600×320、844×390：圓形快門76px且位於視窗中央，無可見文字但能以「拍照」無障礙名稱找到並用Enter拍攝；上方鏡頭控制44px、上下間隔均超過64px、間隔點擊不拍照、快門可達且無橫向溢出。滿寬測試、鏡頭故障／連拍、照片失敗重試與完整取像／浮水印四組通過，無新增失敗。不是實機誤觸率、WebKit或歷史全套綠燈；原生多頁GPS未解限制保留。見[交接](../HANDOFF.md)及[本次驗證](../verification/round-shutter-top-optics.json)。
