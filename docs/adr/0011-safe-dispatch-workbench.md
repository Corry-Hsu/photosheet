# ADR-0011：追加、差異審查與發布競態保護

- 狀態：已採用（本次回溯整理；原始實作時間見PR）。
- 整理日：2026-11-20；核對基準：8258a42。
- 證據與範圍：[PR #30](https://github.com/Corry-Hsu/photosheet/pull/30)及後續資料修正PR；[dispatch-plan.js](../../dispatch-plan.js)、[dispatch-tools.js](../../dispatch-tools.js)、[操作](../dispatch-workbench.md)。

## 背景

使用者反覆追加／移除JSON，要求既有資料不覆蓋、去重，僅特定修正可取代，且不希望每次都依賴人工修改程式。

## 決策／改了什麼

建立獨立工作區讀main/data基準，新案追加，舊案逐欄核准，刪除明確選取；引用中的KML保留。按ID／完整業務鍵辨識，矛盾同ID拒絕；同步修正只限同任務同原值。匯出前再讀基準，不一致即阻擋。

## 為什麼

落實「保留既有資料」並讓差異可看；使用者可以自行整理、預覽、匯出，免放寫入憑證或後端。

## 未採用／已取代的方案

不採Object.assign盲覆蓋、按地號合併不同案件、刪除所有未引用的既有範圍、網路失敗仍以舊基準匯出、在瀏覽器直接寫GitHub。完整快照模式另保留，但不能混淆其取代語意。

## 影響與取捨

下載到實際提交仍有競態，無法鎖其他GitHub提交；需要再核對commit差異。草稿與管理主資料分開；跨入口原值不同不猜測。

## 驗證與後續

對應[規格完成定義](../SPECIFICATION.md#9-可驗證完成定義產品變更)，實際結果及未通過項目見[交接](../HANDOFF.md)。修改此決策時新增ADR並標示本編號被取代的確切範圍，不刪除本紀錄。
